## Stall wiring

- Timer: [companion-stall.ts](../../../apps/web/lib/companion-stall.ts), with 30 s and 60 s placeholders pending LC-0b measurements. Tests: [companion-stall.test.ts](../../../apps/web/lib/companion-stall.test.ts).
- Mission: a timer opens on a question beat (choice, blank or boxes) that is waiting for the learner's answer. It closes when a save is busy, the page is loading, the journal is open, the answer is checked or revealed by a hint, the mission pauses or ends, or the component unmounts. One `setInterval` at 1000 ms runs only while a beat is open ([learn-mission.tsx:307](../../../apps/web/components/room/learn-mission.tsx#L307)).
- Activity: pointerdown, keydown, input and change inside the mission section restart the idle clock ([learn-mission.tsx:329](../../../apps/web/components/room/learn-mission.tsx#L329)). No coordinates or keys are recorded.
- Payload: `CompanionApi.event(name, payload?)` ([companion.tsx:91](../../../apps/web/components/companion/companion.tsx#L91)) and the engine handle ([engine.ts:951](../../../apps/web/components/companion/engine.ts#L951)) pass `{ level }` to `director.onEvent`. Existing callers compile unchanged.

### Judgment calls

1. Read beats do not start the timer. The learner is reading, not stuck. The hint button only appears on question beats, which matches spec section 6 ("point toward hint button if offered").
2. Reopening the same beat after a save or a resume starts a fresh idle window.
3. Activity restarts the idle clock. It does not re-arm a level that already fired, so each level fires at most once per showing.
4. A late tick that finds both levels overdue fires level 1, then level 2.

### Gaps not changed here

- `stall2` in [beats.ts](../../../apps/web/lib/companion-motion/beats.ts) plays Curious, peek and nod. Spec section 6 says level 2 should point toward the hint button, and the beat does not do that yet. `beats.ts` is outside this task's file list.
- `correctFast` and `sessionReturn` stay unwired, as above.
