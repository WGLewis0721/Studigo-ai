# Phase 3 · Room 2 guided Learn reading (historical)

> Superseded by the production Learn → Explore default rollout. The former `PHASE3_ROOM2_ROOM_IDS` canary and `?guided=1` opt-in were retired for the signed-in Learn screen. This document describes early acceptance and is retained as historical implementation evidence. **No learner data wipe is necessary.**

The signed-in room page reads `PHASE3_ROOM2_ROOM_IDS`. A listed room opens Learn as one column under the orange rail, in place of the chat. The mission walks the existing cursor without naming the steps. Briefing is the objective and Continue. Demonstration is the passage and My turn. The learner then taps a line. Check stays off until a line is selected. A hit is marked on that line. A miss marks the line and then shows the correct line. Continue moves on. One unlabeled progress bar. No typing, no ask box, no second navigation. The strip between the nav and the orange divider does not change. Mastery does not change. Every other room keeps the current lesson. The synthetic fixture (`roomId === "fixture"`, `/dev/study`) shows the same mission without saving it.

Embedded Postgres, running every migration in this repo, proved one owned room can start, replay the same request, advance to Show, pause, and read that same step back. A second account is denied. Topic mastery and quiz-attempt counts do not change. That is not a hosted Supabase apply. Do not set `PHASE3_ROOM2_ROOM_IDS` until this migration is applied there.

The learner taps the sentence from the verified excerpt that states the objective. Check records ready or review on the existing reflection field. It is not a grade and it does not write mastery. The cursor still moves Brief → Show → Try → Check → Done in the database so a saved reading can resume, but those names are not on the screen. A one-sentence excerpt is still that one line. The synthetic fixture can switch between an elementary behavior sample and a college net-force sample. Neither sample is saved.

Start calls the existing guarded `/api/learn` lesson for the selected active topic. It requires an actual cited chunk and commits a reading cursor only if that exact chunk is still owned, eligible for the topic, on a readable page, and at the document's current revision. The cursor moves Brief → Show → Try → Check → Done through an owner-scoped, revision-checked database transaction and idempotent request receipt. The screen does not walk those names: the passage is up immediately, Check records the sentence, and the explanation is requested only after a miss. Reload restores that same cursor. No mission action writes mastery, attempts, or readiness. A replaced/denied source cannot advance or replay its old excerpt; Restart requires a fresh cited Learn lesson.

Migration `20261015010000_learn_mission_cursor.sql` must be reviewed and applied before enabling any real room. The preview fixture `/dev/study?mode=coach&frame=phase3&learn=phase3` is synthetic: click Learn in the switcher. The passage, the bar, and the one button are not persisted, and the sample source cannot open. The route is unavailable in production.

This is **not yet Room 2 acceptance**. The tap check is formative and local to the source sentences. It is not an authored question bank, a college course, or a hosted device pass. Do not connect Home's Start action on the strength of this increment. Review four widths, 200% zoom, keyboard/focus, real elementary and college sources, stale/replaced/deleted citations, cross-account denial, reload, double-submit and zero mastery writes on a hosted preview before release.
