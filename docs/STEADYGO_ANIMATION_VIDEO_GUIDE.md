# SteadyGo Animation & Video Generation Guide

This is the canonical production guide for generating SteadyGo assets for Studigo marketing, onboarding, product-launch, social, and motion-graphics work.

It is a **brand-production contract**, not a learning-engine contract. SteadyGo is presentation/personality only. Generated media must never imply that the companion itself awards mastery, grades work, changes progression, or overrides Studigo's grounded learning systems.

## Character identity

SteadyGo is the orange Studigo dragon.

Lock these traits across every generated still and video:

- Small, stylized 3D baby/young dragon with an expressive 12–14-year-old personality.
- Orange body.
- Cream feathered frill-horns and cream center crest.
- Cream ribbed belly.
- Brown eyes.
- Teal embroidered vest with gold filigree.
- Ringed tail ending in a small flame.
- Premium, soft, polished 3D animation-film rendering.
- Friendly proportions; expressive rather than realistic anatomy.
- Personality: funny, mischievous, confident, slightly sarcastic, warm underneath it.
- Speaks English and is comfortable addressing the viewer directly.
- SteadyGo knows he is in a product video and may break the fourth wall.

Do not redesign his face, vest, crest, horn/frill arrangement, tail, body proportions, palette, or material treatment from shot to shot.

## Source-of-truth rule

Never recreate SteadyGo from a text prompt alone when a canonical reference is available.

1. Start from the approved orange-dragon reference already present in the Studigo/Higgsfield production library.
2. Supply that reference to every identity-sensitive image generation.
3. For video, use approved SteadyGo stills as image/start/end/reference inputs whenever the selected model supports them.
4. Prefer a consistent reference-driven model over a nominally stronger model that drifts the character.
5. Reject a beautiful frame if it changes SteadyGo's identity.

When extending the library, generate one new performance variable at a time where practical: angle, expression, mouth shape, gesture, pose, or action.

## Canonical reference library

Maintain enough approved stills to cover future productions without reinventing the character.

## Product-film behavior

SteadyGo should feel as though he lives inside Studigo rather than being pasted over the product.

Use physical UI interaction selectively. Most interface motion should happen naturally around him. In a typical 30-second piece, give him roughly 2–3 memorable rule-breaking interactions: catch a card, push a panel aside, lean on a floating surface, step through a screen boundary, etc.

The interaction should support the story. Do not turn every interface element into a gag.

## Launch-film signature

The introductory Studigo product film uses the existing recognizable SteadyGo opening as its setup.

The intended beat is:

1. Begin like the normal Studigo opening.
2. SteadyGo enters as expected.
3. Something changes: he notices the viewer/camera.
4. He knowingly breaks the normal animation.
5. He jumps **out of the Studigo frame** into a clean motion-graphics space.
6. He takes over the film as its first-person host.
7. He directly walks the viewer through the companion-centered **Learn. Earn. Play.** experience.
8. No game footage is required for this introductory film.
9. Tone progression: familiar → unexpected → impressive → funny → exciting.
10. Desired final reaction: adults think, “I’ve never seen an app like this,” while a child thinks, “Mom/Dad, I like this.”

Target master length: approximately 30 seconds. Compose a master that can be reformatted/cut for website, App Store/launch presentation, YouTube, and vertical social.

## Studigo product truth

The film must preserve Studigo's actual product premise:

> The learner brings their own class materials; Studigo helps them learn those materials.

The companion makes that experience personal, approachable, motivating, and memorable. Do not present SteadyGo as an all-knowing generic tutor detached from the learner's Study Room/materials.

“Learn. Earn. Play.” is the high-level companion loop, but marketing must not claim a reward, economy, game, or progression capability that is not actually shipped or explicitly being presented as future/preview functionality.

## Higgsfield workflow

For current production:

- Use the approved SteadyGo image as the identity anchor.
- Generate still references before expensive video attempts.
- Prefer reference-driven image generation for new canonical poses.
- For character video, prefer models with strong identity/reference support.
- Use start/end frames for important transitions where possible.
- Use motion transfer when an exact body action is difficult to describe reliably.
- Generate short shots rather than asking one model to create an entire commercial.
- Composite the real Studigo interface instead of asking a generative video model to redraw UI text and controls.

At the time this guide was written, Seedance-class reference-driven video and Kling-class multi-shot/motion tools are appropriate candidates in Higgsfield, but model names are **not** permanent brand requirements. Re-evaluate the current catalog before production.

## Real UI rule

Do not generate fake Studigo UI when the real interface can be captured.

Use real app screen recordings, screenshots, exported UI assets, or purpose-built motion-graphics recreations based on the real design. Generative video should primarily handle SteadyGo and cinematic transition material.

This prevents mutated text, fake buttons, invented features, and inconsistent product design.

## Shot-generation discipline

Treat a finished video as a sequence of short controlled shots.

For each shot define:

- Purpose in the story.
- Duration.
- Camera/framing.
- Starting SteadyGo reference.
- Ending SteadyGo reference when useful.
- Exact action.
- Facial performance.
- UI interaction.
- Background/motion-graphics requirements.
- Spoken line or dialogue timing.
- Transition in/out.

Generate alternatives for difficult hero shots, not every mundane shot.

## Quality gate

Do not approve a generated SteadyGo asset if any of these drift materially:

- Orange/cream/teal palette.
- Face or eye identity.
- Crest/frill/horn structure.
- Vest design.
- Body proportions.
- Tail/rings/flame.
- Number or structure of limbs/digits.
- Rendering style.
- Age/personality impression.

Also reject shots with malformed hands/feet, detached UI interaction, unreadable silhouette, inconsistent eye direction, unexplained costume changes, or accidental extra accessories.

Identity consistency beats spectacle.

## File organization

When generated media is exported into the repository or shared production storage, organize by function rather than by generation session:


Do not commit large raw generation dumps to the application repository. Keep only approved production assets that the product or documentation actually needs. Raw/high-resolution source media should live in the designated production-media store.

## Prompt baseline

Use this identity block as the starting point when a tool requires textual identity reinforcement:

> Use the supplied reference as the exact same SteadyGo character, the orange Studigo dragon. Preserve identity precisely: small orange stylized 3D young dragon; cream feathered frill-horns and center crest; cream ribbed belly; brown eyes; teal embroidered vest with gold filigree; ringed tail with a small flame. Preserve the exact proportions, face, costume, materials, colors, and premium soft 3D animation-film rendering of the reference.

Append only the shot-specific performance, camera, expression, and action after that block.

## Future-video rule

Before producing a new SteadyGo video:

1. Reuse existing approved references first.
2. Identify any missing pose/expression/action.
3. Generate only the missing reference stills.
4. Approve identity consistency.
5. Generate short video shots from those anchors.
6. Composite with real Studigo UI.
7. Add the locked SteadyGo voice/dialogue.
8. Edit, sound-design, grade, and master.
9. Add genuinely reusable approved references back to the canonical library.

The goal is cumulative: every Studigo production should make the next SteadyGo production easier and more consistent.
