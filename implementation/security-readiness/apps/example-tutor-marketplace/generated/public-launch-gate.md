## Scope questions

Answer these in `app-profile.json`. Each answer decides whether the listed controls apply.

- **oauth**: Can users sign in with Google, Apple, Microsoft or another OAuth/OIDC provider? _(activates GMS-AUTH-002)_
- **ai_tools_or_agents**: Can a model call tools, APIs, browsers or code, or change data, on its own? _(activates GMS-API-005, GMS-AI-004)_
- **outbound_fetch**: Does the server fetch URLs or call hosts that a user, document or model can influence? _(activates GMS-API-005)_
- **admin_console**: Is there a privileged operator, admin or support interface? _(activates GMS-AUTH-005)_
- **auxiliary_services**: Are there separate workers, microservices, local services, queue consumers or retrieval servers? _(activates GMS-ACCESS-003)_

## Open release blockers

### GMS-GOV-002: Sensitive data classification and lifecycle

- Severity **P0**, status **not_tested**, risk not scored, owner role Legal/Privacy, effort M
- Action: Create a data register (category, location, purpose, retention, deletion path, providers) and implement retention jobs for anything without one.
- Done when: Every stored data category has a classification, purpose, retention period and deletion mechanism. Data sent to each external provider is listed with its retention terms. Retention periods are enforced by code or scheduled jobs, not policy text alone.

### GMS-AUTH-001: Authentication required for private resources

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Centralize auth in one helper per surface (page, route, action), reject anonymous sessions there, and add an inventory-driven negative test.
- Done when: Every private page, API route, server action and RPC rejects unauthenticated callers. Guest/anonymous sessions cannot reach private or paid operations unless the product explicitly intends it. Each private endpoint has an automated unauthenticated negative test.

### GMS-ACCESS-001: Object-level authorization / tenant isolation

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Enforce ownership in the database (RLS or equivalent) and check it in the route before any privileged write.
- Done when: Every object ID accepted from a client (path, query, body) is authorized against the caller, not just validated. Tenant isolation is enforced in the data layer (e.g. RLS) and tested with two real users. Substituting another tenant's ID returns not-found or forbidden on every route.

### GMS-ACCESS-002: Privileged/service-role operations scoped

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Wrap the privileged client in a server-only module and make owner/tenant a required argument of every privileged function.
- Done when: Every use of a privileged (RLS-bypassing/service) credential is listed. Each privileged call is preceded by an ownership check under the caller's identity and passes the owner explicitly. Privileged credentials never reach client bundles.

### GMS-API-002: Rate, concurrency and cost limits

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort L
- Action: Add edge rate-limit rules (log mode first), a per-user usage table checked before provider calls, output-token caps, and provider budget alerts.
- Done when: Expensive routes have per-user and per-IP rate limits enforced at the edge and in the app. Model calls set output-token caps and timeouts; retries are bounded. Per-user daily budgets and a global spend ceiling/circuit breaker exist. Reprocessing/regeneration paths cannot loop without limit.

### GMS-API-006: Inbound webhook authenticity and replay protection

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Use the provider's signature verification helper on the raw body and store processed event IDs.
- Done when: Every webhook verifies an HMAC/signature over the raw body with a constant-time compare. Timestamps outside a tolerance window are rejected. Processing is idempotent by event ID.

### GMS-WEB-002: Untrusted/model output rendered safely

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Render through a parser that emits framework nodes only; add payload fixtures to tests.
- Done when: Model output and user content are rendered as text/structured nodes, never raw HTML. Links and images in untrusted content are disabled or sanitized. An XSS payload regression test exists.

### GMS-FILE-002: Content signature and parser validation

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Check signatures for each allowed format before storage; serve originals with forced download and nosniff.
- Done when: The bytes of every upload are checked against the accepted type (magic bytes / structure). A renamed or polyglot file is rejected before storage or parsing.

### GMS-FILE-003: Archive/decompression/image/OCR resource bounds

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Inspect archive directories before parsing, cap pixels/pages, and run parsing in a worker with resource limits.
- Done when: Archive-based formats are bounded by entry count, expanded size and ratio before inflation. Image dimensions, page counts and OCR pages are capped. Parsers run with time and memory budgets.

### GMS-FILE-004: Malware/quarantine controls

- Severity **P0**, status **not_tested**, risk not scored, owner role Platform/Ops, effort M
- Action: Add scanning (e.g. ClamAV in the ingestion worker or a scanning service) and a quarantined status.
- Done when: Uploads are scanned or disarmed before they are processed or served to anyone. Unscanned or flagged files stay quarantined.

### GMS-FILE-005: Private storage and scoped download

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Keep buckets private, scope storage policies by owner prefix, and issue signed URLs of 5 minutes or less.
- Done when: Buckets holding user files are private. Downloads use short-lived signed URLs issued after an ownership check. Storage policies prevent listing or writing another owner's path.

### GMS-PAY-001: Payment processing delegated and verified server-side

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Use hosted checkout, look up prices server-side and fulfill only from signed webhooks.
- Done when: No card numbers touch application servers or logs. Prices come from server-side configuration, not the client. Entitlements are granted only from verified provider events.

### GMS-AI-001: Uploaded/retrieved content treated as untrusted

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Serialize untrusted data (e.g. JSON envelope), keep it out of system text, and build scope/context directives server-side.
- Done when: Retrieved/uploaded content and anything derived from it (titles, metadata, earlier model output) reaches prompts only inside a delimited untrusted-data envelope. No browser-supplied text is placed in system/developer instructions. Prompts state that untrusted data cannot change instructions.

### GMS-AI-002: Prompt-injection regression suite

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Add injection fixtures to the evaluation suite and run them on every prompt/model change.
- Done when: A versioned corpus of direct and indirect injection cases runs against the production prompt path and model. Results are reviewed and regressions block release.

### GMS-AI-005: Sensitive-data disclosure testing

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Scope retrieval by tenant in the data layer and add cross-tenant decoys to evaluations.
- Done when: Tests show the model cannot reveal another tenant's data, secrets or system prompt contents that matter. Prompts contain no secrets.

### GMS-RAG-001: Permission-preserving retrieval

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort M
- Action: Enforce tenant filters in the search function with security-invoker/RLS; ignore owner parameters from non-privileged callers.
- Done when: Vector search filters by tenant inside the data layer under the caller's identity. Callers cannot widen scope through parameters.

### GMS-PRIV-001: Retention, deletion and export are implemented

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort L
- Action: Implement account deletion/export flows and retention jobs from the data register.
- Done when: Users can delete their account and all derived data, including storage and provider copies where possible. Users can export their data. Retention jobs run on schedule.

### GMS-PRIV-002: Minor/student-data release requirements resolved

- Severity **P0**, status **not_tested**, risk not scored, owner role Legal/Privacy, effort L
- Action: Get a counsel decision on audience; implement an age screen or the COPPA consent flow; document the security program.
- Done when: Counsel has decided the audience (13+ screen or full COPPA compliance) and the decision is implemented. If under-13 users are allowed: verifiable parental consent, separate consent for third-party disclosure, a written security program and a retention limit exist. If schools are customers: contracts meet FERPA school-official criteria.

### GMS-LOG-002: Logs avoid sensitive-content leakage

- Severity **P0**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Log codes and IDs only; add a redaction layer for anything else.
- Done when: Logs and telemetry contain no document content, learner answers, tokens or secrets.

### GMS-SUPPLY-002: Secret scanning

- Severity **P0**, status **not_tested**, risk not scored, owner role Platform/Ops, effort S
- Action: Enable GitHub secret scanning and push protection; rotate anything found.
- Done when: Secret scanning with push protection is enabled on the repository. No live secrets exist in history.

### GMS-AUTH-004: Account creation and credential abuse protections

- Severity **P1**, status **not_tested**, risk not scored, owner role Platform/Ops, effort S
- Action: Disable anonymous sign-in (or bound it), enable CAPTCHA, breached-password protection and auth rate limits, and treat guest sessions as signed out for paid operations.
- Done when: Anonymous/guest sign-in is disabled, or guest accounts are limited by policy, quota and cleanup. CAPTCHA or equivalent bot protection guards sign-up and sign-in. Breached-password checks and a minimum length are enforced by the identity provider, not only the UI. Auth endpoints are rate-limited.

### GMS-API-003: CSRF / request provenance protection

- Severity **P1**, status **not_tested**, risk not scored, owner role Engineering, effort S
- Action: Rely on framework CSRF protection (e.g. server actions' origin check) and add Origin validation to custom mutating routes.
- Done when: State-changing requests with cookie auth are protected by SameSite cookies plus origin checks or CSRF tokens. GET requests never change state.

### GMS-AI-008: Content safety appropriate to the user population

- Severity **P1**, status **not_tested**, risk not scored, owner role Product, effort M
- Action: Add a moderation step on input and output with category thresholds set for the audience and a crisis-response template.
- Done when: Learner/user input and model or user-generated output pass a moderation check before display. Self-harm content routes to a safe-messaging response with resources. Moderation decisions are logged without content.

### GMS-PRIV-003: External provider data flows documented and configured

- Severity **P1**, status **not_tested**, risk not scored, owner role Legal/Privacy, effort M
- Action: Create a vendor register, sign DPAs, and set provider retention/training controls (e.g. store:false).
- Done when: Each provider receiving user data is listed with data types, retention, training use and a signed DPA. Provider settings (e.g. response storage, retention) match the register.

### GMS-PRIV-004: Privacy notice, terms and data-subject requests

- Severity **P1**, status **not_tested**, risk not scored, owner role Legal/Privacy, effort M
- Action: Draft notice/terms with counsel from the data register and link them from sign-up; add a request form or address.
- Done when: Privacy notice and terms are linked from sign-up and the app. The notice lists every provider receiving user data. Access and deletion requests can be submitted and are fulfilled within the stated period.

### GMS-CI-001: Protected production branch and required checks

- Severity **P1**, status **not_tested**, risk not scored, owner role Platform/Ops, effort S
- Action: Enable branch protection with required checks and at least one review.
- Done when: The production branch is protected; direct pushes and force-pushes are blocked. Required status checks include tests and the security gate.

### GMS-OPS-003: Hosting and managed-platform security configuration

- Severity **P1**, status **not_tested**, risk not scored, owner role Platform/Ops, effort S
- Action: Complete each platform's production checklist and re-run its advisor after changes.
- Done when: All owner/admin accounts on hosting, database, AI and source platforms use MFA. Platform security advisors report no unresolved warnings. Secrets are marked sensitive and scoped to the environments that need them; preview deployments are protected and do not use production data unintentionally. Database SSL enforcement, network restrictions, custom SMTP and backups are configured where offered.
